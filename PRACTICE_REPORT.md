# Отчет по практике: DevSolutions HR System

## Введение

Проект представляет собой HR-систему для управления сотрудниками, проектами и учетом рабочего времени. Он состоит из двух частей:
- `Backend` — серверная часть на Go с API и PostgreSQL.
- `Frontend` — клиентское приложение на React и Vite.

## Цели работы

1. Разработать backend API для CRUD-операций по сотрудникам, проектам и записям учета времени.
2. Обеспечить авторизацию и разграничение прав пользователей.
3. Реализовать frontend для взаимодействия с API.
4. Подготовить документацию и инструкции по запуску.

## Реализованный функционал

### Backend

- **Аутентификация**:
  - вход (`/api/auth/login`)
  - регистрация (`/api/auth/register`)
  - получение текущего пользователя (`/api/auth/me`)
  - смена пароля
  - восстановление пароля через токен

- **Сотрудники**:
  - `GET /api/employees`
  - `GET /api/employees/:id`
  - `POST /api/employees`
  - `PUT /api/employees/:id`
  - `DELETE /api/employees/:id`

- **Проекты**:
  - `GET /api/projects`
  - `GET /api/projects/:id`
  - `POST /api/projects`
  - `PUT /api/projects/:id`
  - `DELETE /api/projects/:id`

- **Учет времени**:
  - `GET /api/attendance`
  - `GET /api/attendance/:id`
  - `POST /api/attendance`
  - `PUT /api/attendance/:id`
  - `DELETE /api/attendance/:id`

- **База данных**:
  - PostgreSQL
  - миграции создания таблиц
  - начальные тестовые данные

### Frontend

- **Управление сотрудниками**:
  - отображение списка
  - добавление
  - редактирование
  - удаление

- **Управление проектами**:
  - отображение проектов
  - добавление новых проектов
  - редактирование проекта
  - удаление проекта

- **Учет времени**:
  - отображение записей учета времени
  - фильтрация по сотруднику, проекту, статусу
  - добавление/редактирование записей
  - отображение имени сотрудника вместо ID

- **Авторизация**:
  - хранение JWT токена в `localStorage`
  - получение данных пользователя после логина

## Важные замечания для отчета

- В проекте использованы реальные паттерны разделения ответственности:
  - `internal/handlers` — обработчики HTTP запросов
  - `internal/models` — модели данных
  - `internal/repository` — доступ к БД

- Frontend разделен по модулям:
  - `modules/employees`
  - `modules/projects`
  - `modules/timesheet`

- В процессе работы проверялись:
  - целостность данных
  - корректность API ответов
  - соответствие frontend типов backend данных

## Инструкция по запуску

### Backend

```bash
cd Backend
# Убедитесь, что PostgreSQL работает и доступен по DATABASE_URL
# Пример:
# DATABASE_URL=postgres://postgres:123@localhost:5432/hr_db?sslmode=disable

go run ./cmd/migrate/

go run ./cmd/api/main.go
```

### Frontend

```bash
cd Frontend
npm install
npm run dev
```
